# lib-fetch-js

`fetch-js` — `fetch` over generated WebIDL bindings: the JS-host
counterpart of `fetch-c`. The bindings are codegen output under
`handl-packages/generated/` (gitignored), regenerated from the
committed spec `specs/fetch.idl` (w3c/webref pinned).

## Layout

| path | role |
| --- | --- |
| `src/index.hnl` | the backend module (`fetch-js`) |
| `specs/fetch.idl` | committed WebIDL spec input |
| `handl-packages/generated/` | gitignored bindings — regenerated by the gate |
| `pkg.hnl` | manifest — dep `fetch` only (`js` is a host/builtin contract, NOT a dep — see Contract); `test_coverage: "none"` (all exports need `js.*` host natives) |
| `scripts/hnl-gate.sh` | regenerates bindings, then gates `.hnl` sources |
| `workflows/gate.yaml` | CI — shared `handl-gates` campaign |

## Contract

- Implements the `lib-fetch` contract via the `js` ffi; union-typed
  values marshal through the `js_object` descriptor.
- `js` stays out of `pkg.hnl` `deps` and `.handl.toml`
  `[dependencies]`: the `js` contract is a host/builtin surface
  (compile-js binds `from "js"` to `__handl_rt` shims regardless of
  dep tables). Declaring the dep makes `hnl run`/`hnl test` resolve
  `js` to `lib-js`'s signature-only exports — `call` erases to `null`
  and every call dies with "callee is not an arrow-value". Undeclared,
  the import lowers to the ambient `"js.call"` callee and fails
  honestly as `call_host: function 'js.call' not found` on hosts
  without JS natives (the shape `scripts/hnl-gate.sh` tolerates).
- Never commit `handl-packages/generated/` — edit `specs/` and re-emit
  (`hnl codegen webidl specs/fetch.idl --output handl-packages/generated/fetch`).

## Verification

```bash
HNL=../host-cli/target/debug/hnl scripts/hnl-gate.sh
```
